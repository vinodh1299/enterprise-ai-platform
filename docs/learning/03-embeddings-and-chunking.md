# Phase 3: Document Ingestion Pipeline, Chunking & Vector Embeddings

## Explain Like I'm 10
Imagine taking a 200-page enterprise manual and making it searchable for an AI:
1. **Document Parsing:** Reading PDFs, Word docs, or text files line-by-line and extracting text.
2. **Chunking (Slicing):** You can't swallow a whole pizza at once! We slice the document into bite-sized paragraphs called **Chunks** (e.g., 500 words per chunk with 50 words overlapping so no sentence is cut in half).
3. **Embeddings (Map of Meaning):** 
   Imagine a giant 3D map of the universe. 
   - Words about money (`"Revenue"`, `"Profit"`, `"Sales"`) are placed close to each other on the map.
   - Words about space (`"Planet"`, `"Star"`, `"Galaxy"`) are placed far away on the other side of the map.
   An **Embedding** is simply the GPS coordinates (a list of 384 numbers) of where a text chunk sits on that map of meaning!

---

## Technical Definition
* **Text Extraction:** Parsing document layout structures (PDF streams, docx XML elements) into raw text strings.
* **Recursive Character Chunking:** An algorithm that recursively splits text on natural boundaries (`\n\n`, `\n`, `.`, ` `) to ensure text chunks fit within specified token limits while preserving semantic continuity via sliding window overlap.
* **Vector Embedding:** A high-dimensional numerical vector representation ($\mathbb{R}^d$, e.g. $d=384$ or $d=768$) of text generated by an encoder model (such as `BAAI/bge-small-en-v1.5`), mapping semantic concepts into vector space where geometric proximity reflects semantic similarity.

## How It Works in Our Backend (`POST /api/documents/upload`)

```text
[ Upload File (PDF/DOCX/TXT) ]
              │
              ▼
[ 1. Document Parser ] ──> Extracts raw text page by page (backend/app/ai/rag/parser.py)
              │
              ▼
[ 2. Text Chunker ]   ──> Slices text into overlapping 500-char chunks (backend/app/ai/rag/chunker.py)
              │
              ▼
[ 3. Local Embedder ] ──> FastEmbed computes 384-dim dense vectors ($0 Cost!)
              │
              ▼
[ 4. Database Store ] ──> Stores document & chunk vectors in PostgreSQL (backend/app/models/document.py)
```

## Interview Questions an AI Engineer Could Ask
1. **Q: Why is chunk overlap necessary when chunking text for RAG?**
   * *A:* Without overlap, a critical sentence or key-value pair spanning across the boundary between Chunk A and Chunk B gets sliced in half. Chunk overlap acts as a sliding window buffer, ensuring boundary context is preserved in at least one chunk.
2. **Q: What is the difference between a dense vector embedding and sparse keyword representations (like BM25)?**
   * *A:* Dense vector embeddings encode semantic meaning into continuous floating-point vectors ($\mathbb{R}^{384}$), allowing search by meaning (e.g. matching `"laptop"` to `"notebook"`). Sparse representations (like BM25) count exact token term frequencies, excelling at exact identifier matches (e.g. matching `"ERR-404"`).
